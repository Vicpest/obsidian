# 存储层级、调度与性能分析

Transformer NPU 的实际性能由计算吞吐和数据搬运共同决定。即使 [[npu/operator/tensor operator/GEMM|GEMM]] 阵列很大，若操作数不能及时到达，[[npu/operator/others/PE|PE]] 仍会空闲。

## 存储层级与数据生命周期

```text
HBM / DRAM
  ├─ 模型权重：按 layer / tile 流式读入，尽可能跨 batch 复用
  ├─ 激活：层间传递；短 tile 在 SRAM 驻留，容量不足时写回
  └─ KV Cache：decode 的主要读带宽来源
        │
        ▼
共享 L2 / 片上 SRAM
  ├─ A/B/C tile、Q/K/V tile、Norm 临时统计量
  └─ ping-pong 双缓冲
        │
        ▼
PE 本地寄存器 / accumulator / vector register
```

## 双缓冲流水

典型 tile 循环应重叠搬运和计算：

```text
时间 ──►
buffer 0: DMA load tile 0 ── compute tile 0 ── DMA store result 0
buffer 1:                    DMA load tile 1 ── compute tile 1 ── DMA store result 1
```

若加载时间大于计算时间，则系统受带宽限制；反之计算阵列是瓶颈。调度器必须通过事件或 fence 防止 DMA 覆盖仍在使用的 buffer。

## 算术强度与 Roofline 判断

算术强度约为 `FLOPs / 从 DRAM 搬运的字节数`：

- 高算术强度：大规模 [[npu/operator/tensor operator/GEMM|GEMM]]，通常易于复用权重与激活，偏计算受限。
- 低算术强度：[[npu/operator/tensor operator/Elementwise|Elementwise]]、[[npu/operator/tensor operator/Layout Transform|Layout Transform]]、小 batch Decode，偏带宽或延迟受限。
- 长上下文 Decode：每个新 token 的计算量有限，却需要读取大量历史 [[npu/operator/transformer common/KV Cache|KV Cache]]，往往受 KV 带宽限制。

可用峰值计算能力 `P_peak` 与峰值内存带宽 `BW_peak` 作上界估算：

```text
attainable performance ≤ min(P_peak, arithmetic_intensity × BW_peak)
```

## 调度原则

1. **复用优先**：先安排可复用相同权重或 K/V tile 的任务，减少 DRAM 读取。
2. **融合优先**：将 [[npu/operator/transformer common/Softmax|Softmax]]、Norm、bias、activation 等与生产者/消费者融合，减少中间结果写回。
3. **隐藏延迟**：用 DMA 预取、双缓冲和多 command queue 遮住片外访问。
4. **维持阵列利用率**：对小 GEMM 使用请求批处理、head 合并或更小的子阵列。
5. **隔离资源冲突**：避免多个核同时争用同一 SRAM bank、NoC 链路或 DRAM 通道。

## 性能排查清单

| 现象 | 常见原因 | 优先检查 |
| --- | --- | --- |
| PE 利用率低 | tile 太小、尾块多、DMA 未隐藏 | M/N/K 分块、双缓冲、batch 聚合 |
| Softmax 延迟高 | score 落地、归约串行、SFU 吞吐不足 | [[Attention 硬件实现]] 的 online softmax 和融合 |
| Decode token/s 低 | KV Cache 带宽不足、访问碎片化 | page 大小、K/V 布局、量化、GQA |
| 精度下降 | 累加位宽不足、近似误差、量化 scale 不当 | accumulator、[[npu/operator/tensor operator/Quantization|Quantization]]、SFU 误差 |
| 功耗偏高 | 高频 DRAM 访问、数据重复搬运 | SRAM 命中率、算子融合、权重复用 |

## 稀疏与 KV 的额外计账

- KV Cache 的容量、page table 和历史读取量要一起计入，而不是只看单层 QKV 的 FLOPs；容量公式、分页和生命周期见 [[npu/operator/transformer common/KV Cache|KV Cache]]。
- 稀疏权重的 roofline 应用“压缩 values + metadata + 对齐/搬运开销”作为字节数，不能直接用原始稠密权重大小乘稀疏率。动态 MoE 还必须把 regroup、All-to-All 和慢 expert 的尾延迟计入，见 [[稀疏计算与条件执行]]。
